# ATT&CK-pivot — Decisions log

## 2026-11-02
- Not a PANW project. Open/personal; no Unit 42 internal data. Public sources only (Unit 42 public blog OK as OSINT).
- Coverage input: ATT&CK Navigator layers.
- Probability scope v1: global transition probabilities (Markov, naive first-order acceptable as baseline). Prove on large corpus.
- Still store threat actor, campaign, sector, platform, source, date metadata on every flow/edge observation so actor-conditioned models are a later query, not a re-ingest.
- Storage: Attack Flow has no graph DB (no Neo4j). API uses raw `sqlite3` (storage/database.py + storage/repositories.py, JSON-blob columns); Builder is browser-only; graphs are in-memory networkx. Decision: PostgreSQL + Apache AGE for pivot. Upstream API stays on SQLite in v1 (fork drift), migrate in P5.
- Prior art not a priority; the Markov-chain idea was presented publicly at ATT&CKcon 2.0.
- Sources: open-ended — gov, vendor TI, ISACs, other OSINT. Registry with class/TLP/licence/reliability; incident-level dedupe; TLP:CLEAR-only public exports.
- Required structured sources: MITRE CAR (detection side: DETECTABLE_BY edges, CAR baseline layer, gap→analytic annotations) and VERIS Community Database (via CTID attack_to_veris mapping; mapped_coarse fidelity; tactic-level transitions only where ordered sequence exists; bias cross-check).
- Corpus targets: proceed at 500 incidents / 5,000 ordered transitions (M-Proof); stretch 2,000 incidents.
- Finding: upstream extraction prompt rule 4 chains actions in narrative order without flagging → add order_basis per edge.
- Open: go/no-go thresholds in PRD §5 are proposals pending owner confirmation.

Multi-tactic techniques split weight 1/k across the technique's v20 tactics.
- VCDB transitions are not derived in P1; VCDB is used for the bias diagnostic only.
- Turla emulation plans are now ingested under the "CTID Adversary Emulation Library" source (class `emulation`), per R1.
- **Counting rules (P1.1)** beyond SPEC §7.1–7.2: (a) unlabeled actions (and unknown IDs) have no state but still count as neighbours when deciding START/END, so a node whose predecessor is unlabeled gets no START; (b) START/END need an *eligible* edge (passing the `order_basis`/`fidelity` filters) at the node: a node with no edges, or reachable only through excluded edges, gets neither; the SPEC's literal "in-degree 0 → START" would turn every node of an excluded or unordered flow into a START/END; (c) tactic-level counts are fractional (1/k split for multi-tactic techniques), the incident's contribution to a pair is `min(1, Σ weights)`, so "at most 1 per incident" holds at every level; (d) tactics come from the pinned version's technique table; tactic-only actions are tactic-level states.
- **Credible interval vs. the mean (P1.2/P1.3).** For prior-only cells (n_ab = 0) the marginal `Beta(α·q, …)` has a first shape ≪ 1, so it is extremely right-skewed and the posterior mean `p` can sit above the 95th percentile (743 of the stored rows in the seed-corpus test run; 0 observed cells ever do). Stored exactly as SPEC §7.3 defines (5th/95th percentile); documented in `smoothing.py`; tests assert containment only for n_ab > 0. Open: clamp the displayed interval to include `p`, or show a one-sided "< x" for prior-only cells (P4 UI decision).
- **Model runs (P1.3).** One run stores the requested level plus its ancestors (`technique` → technique + tactic; `subtechnique` → all three). Migration 0002 widens estimate columns to double precision (fractional tactic counts, full-precision hash) and adds `model_run.estimates_sha256` (SHA-256 of the estimates rounded to 10 decimals). `corpus_stats` snapshot: incidents, flows, date range, by source class / TLP / year, edges by `order_basis`, incident-level ordered transitions, unique pairs, pairs with n ≥ 2/5/10. Only one run can be active (partial unique index).
- **Incident dates (P1.4).** Only 2 of the 41 seed incidents carry any timestamp, and one (DFIR - BumbleBee Round 2) uses 1970-01-01 as a relative "day zero". Timestamps ≤ 1970 are now treated as undated. Consequence: the time-based eval split is only possible for dated incidents (1 of 41 in the seed corpus), so P1.5 reports the time split as unavailable on the seed corpus and relies on incident-grouped CV.
- **Evaluation harness (P1.5).** Candidates are the whole destination vocabulary of the level plus END; ties are scored at expected rank (a uniform model gets the mid-rank). ECE is reported over all candidate predictions and over predictions with p ≥ 0.05 (PRD §5). Bootstrap resamples *test incidents* (1,000 by default, seeded). Baselines (co-occurrence, tactic-order) are turned into probability rows so log-likelihood/Brier/ECE are defined for them: co-occurrence floors at 1e-3, scores `b = a` as 0 and gives END its popularity; tactic-order scores 1 vs 0.1. The time split needs ≥ 20 dated incidents and is reported "unavailable" otherwise (seed corpus: 1 dated). `afp model eval RUN [--alpha-sweep 1,5,20,100]` writes `report.md/json`, `reliability.png/json` to `DATA_DIR/pivot/eval/<run>/` and stores the summary in `model_run.eval`. VCDB-vs-rest: tactic-transition counts are derived from VCDB event chains for the *diagnostic only* (268 fully mappable records) and compared by Jensen–Shannon distance; no VCDB data enters a model.
- **α finding (P1.5).** On the 38-incident seed corpus α = 1 over-trusts sparse counts: CV log-likelihood −5.81 (uniform −5.43, popularity −4.65) and ECE(p ≥ 0.05) 0.087; α = 20 gives −4.69 / 0.020 and α = 100 −4.62 / 0.004 with hit@5 0.253–0.257 vs 0.239. α is a hyperparameter to select by cross-validation on the real corpus (P3); the default stays 1.0 per SPEC.

- **Collectors (P2.2).** `afp collect [--source] [--since] [--limit] [--urls FILE] [--files ...] [--tlp]`. Only enabled sources run. robots.txt: 404/410 allow; 401/403/5xx/network error disallow (fail closed). Per-host rate limit = max(source `rate_limit_seconds` (default 5), robots `Crawl-delay`). 401/402/403/407/451 are never retried or worked around. Redirects are followed by hand so each hop is robots-checked. Report text goes to `DATA_DIR/pivot/reports/<sha256>.txt`; dedupe by canonical URL (migration 0004, unique index) and by sha256. RSS sources without a `feed_url` use `<link rel=alternate>` autodiscovery because the seed `base_url` values are HTML pages. ISAC imports require an explicit `--tlp`. Candidate = narrative AND max(cited IDs, LLM estimate) >= 3. `--heuristics-only` decides on cited IDs alone and records `mode: heuristics_only` in `report.triage` (migration 0005). Every LLM call is logged in `pivot.llm_call` (provider, model, tokens, latency). The precision check is `afp triage sample` (writes a CSV without the system's decision) then `afp triage eval labels.csv` (needs >= 0.8); it requires 100 hand-labelled real reports, which do not exist yet.

The pivot parser reads the labels from the action's own outgoing line (also through condition/operator paths). On ingest, an LLM-origin edge without a label gets `inferred_llm`; the upstream-corpus default stays `explicit`. - **Batch extraction (P2.5).** `afp extract [--limit --concurrency --provider --model --api-url --timeout]` takes `candidate` reports (sequence-language ones first, then newest), submits each as a text job (`metadata`: title, source name, the report URL as an external reference, the publisher as author), polls, downloads the `.afb`, and ingests it with `origin='llm'`, `api_job_id`, `report_id`. HTTP work runs in a thread pool; all database writes stay in the calling thread, one transaction per report. - **Dedupe (P2.6).** `afp dedupe [--auto-only]`, `afp dedupe queue`, `afp dedupe resolve ID --merge|--distinct --by NAME`. A pair is a candidate when the incidents share an actor (or both have none), their date intervals are within 45 days, and they share a sector/region, have technique Jaccard >= 0.5, or cite a common URL. Score = 0.25·actor + 0.20·date decay + 0.55·similarity (Jaccard as is, 0.8 for a shared URL, 0.5 for a shared sector/region), then >= 0.75 auto-links (transitively, union-find), 0.5–0.75 goes to the queue (migration 0006), < 0.5 is dropped. Choices the SPEC left open: one known actor and one unknown is *not* a candidate; both-unknown counts as a weak actor signal (0.3, not 1.0); **an undated incident is capped at 0.74 so it is only ever queued, never auto-linked** (a date window cannot be checked); a pair a reviewer marked distinct is never proposed or linked again; URL signals come from the report URL and the flow's `external_references` (victim names are not extracted, so sectors/regions stand in for "shared victim"). Merging keeps the earliest-created incident, moves flows, transitions and report links, widens the dates and deletes the emptied incidents, so every flow stays in exactly one incident; the counting rule (at most 1 per pair per incident) already unions across an incident's flows. VCDB cross-dedupe (victim, date, industry) is not built because VCDB contributes no flows yet.

- **Review queue (P2.7).** `afp review sample|list|show|accept|correct|reject|report` (migration 0007: `flow.review_batch`, `review_edge` verdict log). `sample --batch B` takes unreviewed, LLM-extracted flows with at least one edge that are not in another batch: size = min(ceil(10% of eligible), 50), allocated across source classes in proportion (at least one each), seeded. `correct` applies flip / delete / change-basis / add-missed-edge to `transition_obs` and logs one verdict per edge (`correct`, `flipped`, `basis_changed`, `flipped_and_basis_changed`, `spurious`, `missed`); untouched edges count as correct. `reject` marks every edge wrong and removes the flow from the model (the counting query already skips `rejected`; tested). `report` gives `both_correct` (direction **and** `order_basis`, the PRD §5.4 measure), direction-only and basis-only rates, spurious/missed counts, by source class, and whether the review target is met. **SPEC vs PRD mismatch:** SPEC §6.5 says "min(10%, 50) per batch", PRD §5.4 says "≥ 10% of LLM-extracted flows, min 50". Implemented both: the per-batch size follows SPEC (a cap of 50), and `report` passes only if `both_correct` ≥ 0.85 **and** reviewed LLM flows ≥ max(50, 10% of all LLM flows) (PRD). Unreviewed LLM flows currently still count in the model (only `rejected` ones are dropped); whether the M-Proof model should use only accepted/corrected flows is a P3 decision.
